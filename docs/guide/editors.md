# Editors and debugging

The playground `litescript-pg` contains a **language server** and a **debug adapter**, used by the editors with the standard protocols:

| Command | Protocol |
|---------|----------|
| `litescript-pg --lsp` | [Language Server Protocol](https://microsoft.github.io/language-server-protocol/) on the standard input and output |
| `litescript-pg --dap` | [Debug Adapter Protocol](https://microsoft.github.io/debug-adapter-protocol/) on the standard input and output |
| `litescript-pg --disassemble file.lsc` | Displays the instructions generated by the compiler (see [Assembly language](../reference/assembly.md)) |

The scripts use the extension `.lsc`, the assembly files `.lsa`.

## Visual Studio Code

The extension is in the directory `editors/vscode`:

```bash
cd editors/vscode
npm install
npx vsce package
code --install-extension litescript-0.1.0.vsix
```

`litescript-pg` must be in the `PATH`, or its path must be given by the setting `litescript.playgroundPath`. See the [README of the extension](../../editors/vscode/README.md) for the features, the settings and the debug configurations.

## Language server

The language server works on the open files:

- **Diagnostics**: the syntax errors given by the compiler, and the names that aren't declared in the file nor in the libraries of the playground (initialization option `unknownVariables` or setting `litescript.diagnostics.unknownVariables` to disable them)
- **Completion**: variables visible from the position, members of the classes (`this.`, `MyClass.`), namespaces of the script, libraries (`Math.`, `File.`...), methods of the arrays and the strings, keywords and snippets. While the code contains an error, the names of the last valid version are proposed
- **Hover**, **signature help**, **go to definition**, **references**, **rename**, **highlights**, **document symbols** and **folding ranges**

The names are resolved with the rules of the language: the variables of the function and of the functions that contain it, then the namespace selected by `namespace`, then the global namespace. For a member of an unknown object (`object.name`), every member of the classes with this name is proposed.

Other editors can use it, for example Neovim:

```lua
vim.filetype.add({ extension = { lsc = 'litescript' } })
vim.api.nvim_create_autocmd('FileType', {
    pattern = 'litescript',
    callback = function()
        vim.lsp.start({ name = 'litescript', cmd = { 'litescript-pg', '--lsp' } })
    end,
})
```

## Debug adapter

The debug adapter executes a file in the environment of the playground (standard library and libraries of the playground). The `launch` request takes:

| Argument | Description |
|----------|-------------|
| `program` | The script to execute (required) |
| `args` | The arguments of the script (`Process.args`) |
| `cwd` | The current directory |
| `stopOnEntry` | Stop at the first instruction |

Features:

- Breakpoints on the lines (moved to the next instruction if the line doesn't contain one), with **conditions** and **log messages** (`count is {c.count}`)
- Steps (into, over, out), pause, call stack with the names of the functions
- Variables: local variables and `this`, variables of the enclosing functions (closures), namespace, global variables of the script; arrays, instances, classes and namespaces can be expanded and the values modified
- Debug console and watch expressions, evaluated in the current function (`var` and assignments are possible); hovers and outer frames only read variables (`a.b[0]`)
- Stop on the **uncaught errors** with the call stack at the position of the error
- The output of the script is sent to the editor, `Process.exit(code)` ends the session with the code

Limits: the standard input is used by the protocol, so `Console.readLine()` gives `null` while debugging. The breakpoints are only in the debugged file.
